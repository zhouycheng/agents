# Workstation configuration project

This module manages the desired configuration for one macOS development workstation. Package intent, shell configuration, Gradle mirrors, Android/Flutter preparation and GUI environment are declared in `macos/manifest/`. Codex consumes global rules and navigation from `../codex/`.

Start with `bin/workstation check` and `bin/workstation inventory status`; read `README.md` and the matching workstation skill in `../skills/` before changing a component. `check` is read-only. `inventory refresh` observes the local machine and writes only `~/.local/state/env/inventory.json`. Its timestamp and `status` fields determine whether a targeted recheck is needed. A fresh inventory is a navigation aid, not proof that a command will work in the current process.

`bin/workstation apply codex|shell|android|gui` deploys one named component; `verify` checks deployed files. For packages, first show the observed difference and agree on each installation or configuration change with the user. The Brewfile records intent; it does not authorize a bulk installation. On Android/Flutter upgrades, check actual templates and trustworthy checksums, then run `android_env check → prepare → verify`; normal shell startup never downloads distributions. Proxy application modes and switches, including system proxy and TUN changes, are controlled by the user. For tests requiring a different network state, provide manual steps and record the state the user supplies.

Global Codex rules live in `../codex/AGENTS.md` and deploy to `~/.codex/AGENTS.md`. Machine observations, credentials, caches, project builds and user apps stay outside Git. Preserve existing user files when a target is not recognizably owned by this project. Wiki records design and incidents; it is not a live inventory.
